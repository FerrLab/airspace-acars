# Engineering standards for AI agents

This file is the contract for any AI agent (or human) changing this repository.
Read it in full before the first edit. Where it disagrees with the README, this
file wins; where it disagrees with the code, the code is the bug or this file
needs a PR.

Rules use MUST / MUST NOT for things that fail review, and SHOULD for defaults
that need a stated reason to deviate from.

## 1. What this project is

Airspace ACARS is a Wails v3 desktop app: a Go backend and a React/TypeScript
webview. It reads telemetry from MSFS (SimConnect) or X-Plane (UDP), reports
positions to a virtual-airline tenant API, and gives the pilot chat, NOTAMs,
documents, a logbook and audio. It runs for hours on a pilot's home machine
with a flaky network, so **nothing may lose flight data, leak a token, or spam
the error tracker**. Those three constraints explain most of what follows.

## 2. Layout and dependency direction

```
main.go, services.go, *_windows.go     package main: wiring only. Wails service
                                       wrappers live here because binding
                                       generation scans this package.
internal/domain/                       plain types and pure functions. Imports
                                       nothing from internal/.
internal/app/                          the application layer. Imports domain,
                                       profiles, observability. NEVER imports
                                       an adapter.
internal/adapters/<name>/              one package per external thing: airspace
                                       (HTTP API), simconnect, xplane, storage
                                       (SQLite), wails (event bridge), discord,
                                       winaudio. Imports domain and
                                       observability. NEVER imports app.
internal/profiles/                     aircraft profile schema, matching and the
                                       weekly-generated builtin/*.json.
internal/simconnect/                   raw SimConnect DLL binding (Windows).
observability/                         Sentry wrapper, scrubbing, Transient().
cmd/hubhop/                            profile generator CLI.
frontend/src/                          React. components/, components/ui/
                                       (shadcn), context/, hooks/, lib/, locales/.
frontend/bindings/                     GENERATED by `wails3 generate bindings`,
                                       gitignored. Never edit, never commit.
docs/                                  feature docs; docs/plans and
                                       docs/superpowers hold design docs.
```

Dependency direction is **domain ← app ← adapters ← main**. The compiler does
not enforce it, so you MUST. Check with `go list -deps` if unsure.

Two things in the tree are not what they look like:

- `internal/ports/` is **dead code**: nothing imports it. The real driving port
  is `services.go`. Do not add to `internal/ports/`; a dedicated PR should
  delete it.
- The README's "Project Structure" block describes an older flat layout. Use
  the table above.

## 3. Architecture rules

### 3.1 Driven ports are consumer-owned interfaces

The interfaces an adapter implements (`AirspaceAPI`, `Storage`, `UIEmitter`,
`DiscordPresence`, `domain.SimConnector`) are declared where they are
*consumed*, in `internal/app/app.go` or `internal/domain`, not in the adapter.

- Add a method to a port only when the app needs it. Keep ports narrow; a test
  stub has to implement every method (`internal/app/stubs_test.go`).
- An adapter MUST NOT reach back into `app`. It gets what it needs through
  constructor arguments or registered callbacks, as `OnUnauthorized` does.
- New external integrations get a new package under `internal/adapters/`, a
  new interface in `app`, and wiring in `main.go`. Not a new field of type
  `*http.Client` inside `App`.

### 3.2 No god objects: extend by composition, not by adding to `App`

`internal/app.App` already carries sim, recording, flight, profile, settings,
auth, audio, update and Discord state, each behind its own mutex. It is at the
limit. The rule for new work:

- A new feature is a **new type with its own state and its own lock**, in its
  own file, that `App` holds and delegates to. `positionUploader` in
  `internal/app/position_upload.go` is the model: constructed by `App`,
  owns its goroutine, exposes `Submit`/`Stop`, tested on its own.
- You MUST NOT add a new mutex to `App`. If a new field needs locking, it
  belongs in a new type.
- Methods on `App` SHOULD be orchestration: take the lock, read or update
  state, call a collaborator, emit an event. Parsing, math, and policy
  decisions go in `domain` or in the feature type, where they are testable
  without an `App`.
- When touching an existing `App` method that has grown past a screen, prefer
  extracting the piece you need into a function or type over adding to it.

Same rule in the webview: `my-flights-tab.tsx` (970 lines) and
`documents-tab.tsx` (717) are the ceiling, not the template. A new tab is a
small container component plus focused children and a `lib/` module for the
pure logic.

### 3.3 Size signals

These are review triggers, not hard limits. Crossing one requires a sentence in
the PR saying why splitting would be worse.

| Unit | Signal |
|---|---|
| Go file | > 500 lines |
| Go function | > 60 lines, or > 3 levels of nesting |
| React component file | > 300 lines |
| React component | > 6 `useState` calls (reach for a reducer or a hook) |
| Function parameters | > 4 (pass a struct) |

### 3.4 Typed data at the boundary

- Anything returned to the webview through a service in `services.go` SHOULD
  be a `domain` struct with JSON tags, so the generated TypeScript bindings
  carry a real type. `map[string]interface{}` returns (`GetBooking`,
  `GetPilot`, `GetRecordingInfo`) are legacy; do not add more.
- JSON from the tenant API is decoded into a struct in the `app` or `domain`
  file that owns the feature. Tolerate the server's variants there (numeric
  or string IDs, `data`-wrapped or flat), once, with a test, as
  `internal/app/notam.go` does. The frontend MUST NOT re-parse server shapes.
- Wails events are registered in `main.go`'s `init()` with their payload
  type. Adding an event means adding it there and documenting the name
  where it is consumed. Event names are string literals in both languages;
  grep for every use when renaming.

### 3.5 Platform-specific code

Windows-only code lives behind build tags with a matching `_other.go`
fallback (`embed_dll_*.go`, `winaudio/label_*.go`,
`simconnect/adapter_stub.go`). Every package MUST build on Linux: CI runs
there, and so do most agents. If you cannot test the Windows path, say so in
the PR.

## 4. Go conventions

### 4.1 Formatting and vetting

- `gofmt` clean. Run `gofmt -l .` and fix what it lists in files you touched.
  Some files are already unformatted (`internal/domain/flight_data.go`,
  `internal/profiles/profiles_test.go`,
  `internal/app/fallback_test.go`, `mock_sim_connector_test.go`); format
  them only in a PR that is already changing them, so the diff stays readable.
- `go vet ./...` clean for the packages you touched.
- Match the file you are in on `any` vs `interface{}`; `internal/profiles`
  uses `any`, the rest still uses `interface{}`. New packages use `any`.

### 4.2 Errors

- Wrap with context and `%w`: `fmt.Errorf("marshal body: %w", err)`. The
  message says what was being attempted, lowercase, no trailing punctuation.
- A non-2xx HTTP reply is not a transport error. Use
  `domain.NewStatusError(method, path, status, body)` and let callers decide
  with `errors.As`. Never unmarshal a body before checking the status.
- Classify before reporting. `observability.Transient(err)` says whether a
  failure is the network being the network; such errors are logged at
  `Warn`/`Debug` and absorbed (outbox, retry), never raised as a fault.
  `StatusError.Temporary()` (5xx) feeds into this. Keep that contract.
- Sentinel errors are package-level `var errX = errors.New(...)` with a doc
  comment, compared with `errors.Is`.
- Do not swallow errors. `_ = f()` needs a comment saying why the result does
  not matter.

### 4.3 Logging and observability

- `log/slog` with key-value pairs; never `fmt.Println`, `log.Printf` or
  string-formatted messages. Keys are `dotted.lowercase` (`sim.adapter`,
  `http.status`). `log.Fatal` is allowed only in `main.go` before the window
  exists.
- Every `slog.Error` becomes a Sentry report. Use `Error` for something a
  developer must act on, `Warn` for something the pilot should know about,
  `Info` for lifecycle, `Debug` for the one-per-second loops. A loop that can
  fail every tick MUST downgrade to `Debug` after the first report, as
  `connectSim` does with `simWaitFailures`.
- Wrap each external call or state transition in a span:
  `ctx, span := observability.Start(ctx, "area.verb", kv...)`,
  `defer span.Finish()`, `span.Fail(err)` for a fault, `span.Expected(err)`
  for a failure that is part of normal operation.
- Every goroutine that outlives its caller MUST begin with
  `defer observability.Recover()`.
- Counters and gauges: `observability.Count/Add/Gauge` with the same
  `area.noun` naming. See `docs/observability.md` before adding one.
- Nothing identifying the pilot's machine or person goes into a log line, a
  span attribute, a breadcrumb or an error message. Tokens, device codes,
  search text, file paths under the profile directory: all out. The scrubber
  is a backstop, not a licence.

### 4.4 Concurrency

- Document what each mutex guards in the struct comment and keep that true.
- A method that must be called with a lock held carries the `Locked` suffix
  (`closeSimLocked`, `startDataStreamLocked`) and says which lock in its doc
  comment. A method without the suffix takes its own locks.
- Never call out (HTTP, SQLite, `UI.EmitEvent`, another lock) while holding a
  mutex. Copy what you need under the lock, release, then call.
- Goroutines stop through a channel or `context` that the owner closes
  (`stopCh`, `streamStopCh`). No goroutine checks a bare `bool` to exit.
- Fields touched only from one goroutine say so in a comment
  (`autoStartArmed`), and that promise is kept.
- Timing constants (`stalenessThreshold`, `uploadBackoff`) are package-level
  with a doc comment explaining the number. Tests shorten them through a
  helper like `quickRetries(t)` that restores them in `t.Cleanup`; tests do
  not `time.Sleep` to wait for behavior.

### 4.5 Comments

The existing code sets the bar: comments explain **why**, name the failure that
motivated the code, and cite the Sentry issue when there is one. Follow it.

- Every exported identifier has a doc comment starting with its name.
- A constant's comment says what the number trades off.
- A comment that restates the next line is deleted.
- A workaround names what it works around and when it can go.
- No `TODO` without an owner and an issue or PR reference. The tree has none
  today; keep it that way.

## 5. Frontend conventions

- Files are `kebab-case.tsx`; a component's test is next to it as
  `name.test.tsx`; pure logic is in `src/lib/name.ts` with `name.test.ts`.
- `components/ui/` is shadcn output. Regenerate with `npx shadcn add`; do not
  hand-edit beyond what the shadcn docs describe.
- Backend calls go through the generated bindings
  (`import { X } from "../../bindings/airspace-acars"`), never through a
  hand-written fetch to the tenant. Events come from
  `@wailsio/runtime` `Events.On` and the unsubscribe function MUST be
  returned from the effect.
- Async effects set a `cancelled` flag in cleanup and check it before every
  `setState` (`notams-tab.tsx`). Tenant-scoped views remount on tenant change
  with a `key` so no stale reply lands in the new company.
- Every user-visible string goes through `t("area.key")` and exists in all
  four locale files (`en`, `es`, `pt`, `fr`). `locale-parity.test.ts` checks
  some prefixes; add yours to it. Error strings from Go are mapped in
  `lib/translate-error.ts`, not matched inline.
- Rich text from the server is rendered only after `lib/document-sanitize.ts`
  (DOMPurify allowlist). External links open through the backend
  (`OpenDocumentURL`), never `window.open` on server-provided URLs.
- `strict` is on but `noImplicitAny` is off for legacy reasons. New code
  MUST NOT introduce `any`; type the event payloads you consume.
- Styling is Tailwind through `cn()` from `lib/utils.ts`. No inline style
  objects except for computed geometry (maps, sliders).
- New dependencies need a sentence in the PR. Pin versions; the existing
  `"@wailsio/runtime": "latest"` is a wart to remove, not a pattern.

## 6. Testing

### 6.1 What a test looks like here

- Name the behaviour, not the function:
  `TestFailedUploadGoesToTheOutbox`, not `TestSend`. A failing message says
  what is broken for the pilot: `"outbox holds %d of 40 samples; the rest are
  gone"`.
- A short comment above a test or group states the contract it protects.
- Fakes are small structs in `_test.go` files that embed or copy the stub in
  `stubs_test.go` and override one method. No mocking framework.
- Table tests for variants of one behaviour; separate tests for separate
  behaviours.
- No sleeps, no real network, no real filesystem outside `t.TempDir()`.
- Frontend: React Testing Library, query by role and visible text (through
  the `en.json` keys), mock bindings with `vi.spyOn(Service, "Method")`,
  `cleanup()` and `vi.restoreAllMocks()` in `afterEach`.

### 6.2 What must be tested

- Every bug fix lands with a regression test that fails before the fix.
- Every parser of a server shape has a test per accepted variant and one for
  garbage input.
- Every retry, backoff, or give-up path is tested with shortened timings.
- Every security boundary (sanitizer, scrubber, bounded reader, URL
  interception) has a test that asserts the bad input is rejected **and** a
  test that ordinary input survives. Redaction that eats the diagnosis is a
  bug too.
- Profile JSON under `internal/profiles/builtin/` is validated by
  `go test ./internal/profiles/...`; a hand-edited profile MUST drop its
  `x-generated` marker or the weekly workflow overwrites it.

## 7. Security and privacy

- Only the pilot-token routes under `/api/v2/acars/` are called. No
  administrative API key is ever embedded or read from settings.
- A 401 signs the pilot out through `OnUnauthorized`; do not add per-feature
  401 handling. A 403, 404, 429 or malformed body is shown as what it is,
  never as an empty successful list.
- Response bodies are read through `readBounded`; add nothing that
  `io.ReadAll`s an upstream body.
- Secrets never appear in logs, spans, error messages, test fixtures or
  commit messages. If you must reference one, say where it lives.
- The microphone is never read; see the README's audio note before touching
  device enumeration.

## 8. Workflow

### 8.1 Before you start

1. Read the feature's doc in `docs/` if one exists, and the test file next to
   the code you are changing.
2. For anything touching more than one layer or adding a goroutine, write a
   short design note first in `docs/plans/YYYY-MM-DD-<topic>-design.md`
   (goal, approach, span points, what is out of scope) and get it approved.

### 8.2 Verifying before you push

Headless environments (CI runners, agent containers) lack GTK/WebKit, so the
root package and the `wails` adapter will not compile there. These commands
are known to work without a display:

```bash
# Go: everything that does not need the webview toolchain
gofmt -l . && go vet $(go list ./... | grep -v -e '/adapters/wails$' -e '^airspace-acars$' -e '/build/')
go test $(go list ./... | grep -v -e '/adapters/wails$' -e '^airspace-acars$' -e '/build/')

# Frontend
cd frontend && npm ci && npm test
```

With the Wails CLI and system libraries installed (see README), also run:

```bash
mkdir -p frontend/dist && touch frontend/dist/.gitkeep   # root package embeds it
go build ./... && go test ./...
wails3 generate bindings -ts                               # when services.go changed
cd frontend && npx tsc --noEmit
```

`tsc` is not in CI and fails without generated bindings; the two
`auth-context.test.tsx` TS2554 errors are pre-existing. Do not add to either
list.

If `services.go` gained or changed a method, the bindings changed; frontend
code that calls it needs the mock in `frontend/src/__mocks__/` updated too.

### 8.3 Commits and pull requests

- Conventional Commits: `type(scope): imperative lowercase summary`.
  Types: `feat`, `fix`, `refactor`, `test`, `docs`, `build`, `ci`, `chore`.
  Scopes are feature areas as used in history: `sim`, `xplane`, `simconnect`,
  `flight`, `position`, `auth`, `api`, `chat`, `notams`, `documents`,
  `my-flights`, `audio`, `settings`, `update`, `profiles`, `discord`,
  `observability`, `frontend`, `deps`.
- The body explains why, in prose, and names the user-visible effect. One
  logical change per commit; formatting-only and generated-file changes are
  their own commits.
- A PR description states: what changed, why, how it was verified (paste the
  commands from 8.2 that ran), and anything not verified (e.g. "Windows path
  untested"). Reviewers should not have to read the diff to learn the risk.
- Never commit `frontend/bindings/`, `frontend/dist/`, `bin/`, `*.exe`, or a
  modified `SimConnect.dll` / `hubhop` binary.
- Docs move with code: a behaviour change updates the README feature list and
  the relevant `docs/*.md` in the same PR.

### 8.4 Definition of done

- [ ] Dependency direction intact; no new mutex on `App`; no new `any` or
      `map[string]interface{}` at a service boundary.
- [ ] Tests added for the behaviour and for the failure path; all commands in
      8.2 pass, output included in the PR.
- [ ] Every new string in four locales; every new event registered in
      `main.go`.
- [ ] No secret, token or pilot-identifying value in logs, spans, tests or
      the diff.
- [ ] Comments say why; exported identifiers documented; constants justified.
- [ ] Commit messages follow 8.3; docs updated; generated files not
      committed.

## 9. Known debt (do not fix in passing)

Each of these deserves its own PR with its own tests. Note them, do not
bundle them into unrelated work.

- `internal/ports/` is unused and duplicates `services.go`.
- README "Project Structure" is stale.
- `gofmt` drift in the files listed in 4.1.
- `App` is at its size limit; candidates for extraction into their own types:
  auth state, audio cache, update state.
- `my-flights-tab.tsx` and `documents-tab.tsx` exceed the component size
  signal.
- `"@wailsio/runtime": "latest"` is unpinned.
- `tsc --noEmit` is not run in CI and has two pre-existing errors.
